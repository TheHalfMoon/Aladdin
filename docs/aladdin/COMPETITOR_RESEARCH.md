## Competitor assessment (all task results NOT MEASURED)

| Product / evidence | What to learn, present Aladdin gap, and comparison limit |
|---|---|
| Desktop Commander, source+installed0.2.52 | Broad files/search/edit/terminal sessions are implemented in source and ahead of Aladdin's unarmed shell breadth. Preserve convenience with enforced Aladdin boundaries; compare same MCP planner/config and authorized scope. Generic eval is not an established exploit. |
| [TinyFish current docs](https://docs.tinyfish.ai) | Five surfaces: Agent, Research, Search, Fetch and remote Browser with Playwright/CDP; context profiles are documented. Aladdin is behind in complete browser research workflows. Hosted service has costs/egress; do not treat MIT AgentQL examples as the engine. |
| [Claude computer use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) | Model plans, client executes; current batched toolset and developer approval hooks are documented. Borrow bounded failure handling; compare executor separately from model. Structured companion tools can exist, so pixels-only generalization is incomplete. |
| [OpenAI computer API](https://developers.openai.com/api/docs/guides/tools-computer-use) | Ordered actions/client executor and Playwright reference integration; structured tool ecosystem is separate. Aladdin can be an execution adapter, but account/client interoperability must be tested. |
| ChatGPT computer-use products | Current help page says legacy ChatGPT agent is no longer available and links Work/cloud-browser successors, while old availability text remains below. The [current cloud-browser guide](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt) documents remote public/signed-in browsing, website-specific access permissions, consequential-action confirmation, secure sign-in and takeover. The [Work/Codex guide](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex) distinguishes longer tasks from software work. These are SOURCE-DOCUMENTED features, not local Windows control or measured results. Website grants/confirmations/takeover are therefore not unique to Aladdin. |
| UI-TARS Desktop, pinned source | Action parser and desktop-agent UX/loop are useful; local model/Electron stack is outside the thin-client goal. Model benchmark score does not establish complete-product superiority. |
| browser-use, pinned source | DOM serialization, lifecycle/watchdogs and agent recovery; do not import a second whole planner framework merely for browser actuation. |
| Stagehand, pinned source | act/observe/extract and cached/browser-extension ideas; debugger/all-host permissions require reviewed scoping. Hosted runtime and local source are different layers. |
| MeshCentral/MeshAgent, pinned source | Mature outbound remote management, inventory and visible sessions; Aladdin's target-granted two-machine journey is currently incomplete. SYSTEM service/KVM/fleet stack is unnecessary for v1. |

Potential Aladdin advantages are native generation-bound Windows semantics, enforced local authority with server-independent Core, transparent egress and independently verified task receipts across targets. Each is a direction to test. Typed targets, human approvals, structured browsers, remote control and encrypted channels individually are not unique features. An auditable combination with a simple Windows UX may differentiate.

Do not copy competitor capability matrices containing N/absent without defining the specific API/executor/configuration and checking current source. Unobserved telemetry/approval/remote behavior is UNKNOWN, not absent. Holo4 and OSWorld2 headline scores may differ by release, metric, harness or date; reconcile those before comparison, rather than declaring conflict or saturation from trackers.
