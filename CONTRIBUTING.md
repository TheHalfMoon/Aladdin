# Contributing to Orcel

Thank you for helping make trustworthy computer-use tooling more useful and auditable. Orcel is an **Apache-2.0-licensed** open-source project. Contributions to documentation, accessibility, tests, security hardening, and code are welcome.

Before opening a pull request, read the [README](README.md), [security policy](SECURITY.md), [code of conduct](CODE_OF_CONDUCT.md), and the [current architecture and delivery plan](docs/canonical/ARCHITECTURE_AND_DELIVERY_PLAN.md).

## Choose an issue

- For a reproducible problem, open a [bug report](https://github.com/TheHalfMoon/Orcel/issues/new/choose).
- For an improvement, open a [feature request](https://github.com/TheHalfMoon/Orcel/issues/new/choose) describing its use case and risks.
- For a first contribution, look for suitable issues on the [issue tracker](https://github.com/TheHalfMoon/Orcel/issues). Do not assume a particular label exists or that a proposed feature is approved.
- **Security issues must be reported privately**, via [GitHub's private vulnerability reporting](https://github.com/TheHalfMoon/Orcel/security/advisories/new). Do not post exploit details in an issue or pull request.

## Local development

The shipped installer is **Windows x64**; some tests and device integrations are Windows-only. The repository also runs cross-platform Rust, Node, and web checks in GitHub Actions. Use a recent stable Rust toolchain, Node.js 20+, npm, and a supported Windows environment for native qualification.

```sh
git clone https://github.com/TheHalfMoon/Orcel.git
cd Orcel
npm ci --ignore-scripts
npm run build
npm run typecheck
npm test
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

For the isolated website:

```sh
npm ci --prefix apps/web --ignore-scripts
npm run web:typecheck
npm run web:test
npm run web:build
```

For changes to the visual identity, run `node scripts/sync-brand.mjs --check` and review [the identity specifications](assets/brand/IDENTITY.md). Site and brand assets are checked and generated by CI. If a native or platform-specific check cannot run locally, clearly state why; never label it passed.

## Pull-request expectations

1. Branch from the latest `main`. Keep changes focused and avoid unrelated refactors.
2. Explain **what changed, why, what it affects, how it was tested**, and any limits or dependencies. Provide before/after examples where helpful.
3. Preserve current authorization boundaries: workspace trust, one-time local approvals, Windows Hello for high-risk actions, protected data, process containment, and fail-closed defaults.
4. Do not weaken tests, ignore warnings, invent CI receipts, or modify historical evidence/attestations to make a change look complete. Follow the repository's [Diffcipline](docs/governance/DIFFCIPLINE.md) and applicable qualification gates.
5. Add tests for behavioral changes. For visual/UX changes, include screenshots or SVG previews without real secrets or user data.
6. Never commit credentials, tokens, personal datasets, private machine paths, or third-party source with unclear redistribution rights.
7. Check upstream licenses and attribution before adding or copying third-party work. See [dependency/license research](docs/research/DEPENDENCY_LICENSE_REVIEW.md) and retain the license notices required by those components.
8. Submit a PR using the supplied template and address review comments. A passing CI build is necessary but not a guarantee of acceptance or release.

Contributions are provided under the repository's [Apache License 2.0](LICENSE), unless explicitly identified as third-party material under its own compatible terms. Contributors must have the right to submit their work. Do not place confidential permission documents in public pull requests.

## Communication

Please be specific, respectful, and evidence-driven. If a change touches release procedures, trust policy, or any authority boundary, **discuss its design before implementing it**. Review and merge depend on maintainer availability and project requirements; no response or merge time is guaranteed.
