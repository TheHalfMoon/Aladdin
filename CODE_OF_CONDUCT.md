# Orcel Community Code of Conduct

Orcel aims to be a welcoming, professional open-source project where people can debate technical decisions without personal attacks. This policy applies to project issues, pull requests, review comments, and other community spaces managed by the project.

## Expected behavior

- Be respectful to people with different backgrounds, skill levels, and viewpoints.
- Offer actionable, evidence-based feedback about code and design rather than judgments about contributors.
- Assume good intent where reasonable, acknowledge mistakes, and help newcomers find relevant documentation.
- Respect other people's privacy, copyright, and licensing obligations.
- Keep security-sensitive information out of public discussions.

## Unacceptable behavior

Harassment, discrimination, threats, sexualized attention, hate speech, doxxing, stalking, deliberate disruption, and repeated personal attacks are not welcome. Technical disagreement is expected; targeting or humiliating a person is not.

## Reporting and response

If you experience or witness conduct that violates this policy, contact the maintainers through an available **private contact method** on their GitHub profiles. Where appropriate, use GitHub's built-in abuse reporting controls. Do not publish sensitive personal information to demonstrate the issue.

For **software vulnerabilities**, use [private vulnerability reporting](https://github.com/TheHalfMoon/Orcel/security/advisories/new) instead of a conduct report.

Maintainers may ask for clarification, remove abusive comments, request a change in behavior, lock discussions, or restrict participation. Actions will be based on available evidence, severity, and context. Reports are handled discreetly where practical, but absolute confidentiality cannot be promised on external services.

Maintainers are also expected to follow this code. This is an original project policy, informed by common open-source community practices.
