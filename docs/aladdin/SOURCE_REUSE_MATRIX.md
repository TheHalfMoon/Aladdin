## Firecrawl permission update

The founder explicitly states permission to copy all Firecrawl source and use it freely. No Firecrawl code is copied, adapted or distributed until that written grant is on file and verified at source admission. Treat that as a founder-reported direct grant; do not continue categorically rejecting source reuse because the public root is AGPL. Independently, the public root still is AGPL-3.0 and API package metadata says ISC; the metadata discrepancy is not proof the entire codebase is ISC. Retain the written rightsholder grant, scope/entities/derivatives/commercial distribution/hosting/notices and covered revisions. Third-party components and trademarks may have separate rights.

Preferred first use: bounded content extraction and result formatting, isolated behind Aladdin's approved network/egress contracts. html-to-markdown.ts depends on config/logger, Go FFI or HTTP service, Rust postprocessing and JS fallback; it is not a standalone dependency-free snippet. Select one path with time/size limits and an independent fixture corpus. search/transform.ts is a smaller formatting candidate. Crawler code depends on queue/storage/robots/filtering; adopt a separately operated service only when real research workflows need multi-page crawling. Firecrawl complements live browser sessions; it does not substitute for local signed-in desktop browser authority. No Firecrawl source was imported by this review.

## REA and Desktop Commander verification

Opus lists an exact registry tarball/integrity, registry gitHead and output hash, but its large raw artifact and input file manifest were not available in the repository. Placeholder global npm paths and changing installed content prevent exact replay. The report distinguishes full-package OOM from scoped analysis; those run durations/file/AST totals remain **secondary evidence**, not independently measured here.

A fresh REA checkout is 6.1.0 at the revision above. `rtk proxy node scripts/rea.mjs doctor --json` exits 1 with 'compiled runtime is missing'. No REA analysis was independently run and no toolchain was installed to simulate the earlier result. Native decompiler availability in Opus's historical host is not a universal capability claim about today's REA.

Independently inspected Desktop Commander source and installed 0.2.52 dist show remote feature flags gating model-visible onboarding, with local/CLI/client exclusions and bounded display frequency. The inspected invitation text is bundled/static; remote activation is evidenced, arbitrary remotely supplied text/code execution is not. Keep useful file/session implementations but omit vendor instruction injection from tool results. Worker `eval:true` executes a fixed worker-program string with controlled module imports; user text/query appears as worker data. That pattern alone is not attacker-controlled eval or RCE. Child-process/network imports similarly require a traced untrusted-input-to-effect path before a vulnerability label.

A reproducible future REA run needs exact registry bytes/integrity, source/build pin, CLI/options, Node/OS/toolchain, input path manifest+hashes, bounded resources, output digest algorithm and raw artifacts with redaction/access policy. Its findings assist review; they do not qualify a donor by themselves.
